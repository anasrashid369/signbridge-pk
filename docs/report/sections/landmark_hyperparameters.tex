\section{Landmark Hyperparameter Search}
\label{sec:landmark-hyperparameters}

\subsection{Search Space}

The tuning grid is stored in \texttt{configs/landmark.yaml} and read by \texttt{python -m signbridge.tune\_landmark}. The SVM and the random forest use their full grids: $4\times4=16$ SVM trials and $3\times3=9$ forest trials. The MLP grid has five hyperparameters with three values each, $3^5=243$ combinations, which is too many to train. A seeded random sample of 20 combinations is run instead (Table~\ref{tab:landmark-search-space}). At most $16+9+20=45$ trials are therefore run. Each trial appends one row to \texttt{reports/tuning/landmark\_trials.csv}, which has its own columns for the SVM, forest and MLP parameters. A trial that is already in the file is skipped, so an interrupted search can be resumed. Every trial is trained on the training split and scored on the validation split. The test split is never read during tuning.

The remaining settings are fixed during tuning: two hidden layers, at most 100 epochs, early-stopping patience 10, AdamW, 63 inputs, 26 classes and seed 42. Every SVM trial fits the \texttt{SVC} about six times because of the calibration (Section~\ref{sec:landmark-models}), so the SVM grid is the most expensive part of the search.

\subsection{Selection Rule}

Within each model family, the trial with the highest validation macro-F1 wins. Macro-F1 is used because it weights all 26 letters equally and shows letters that fail, even though the classes are balanced. The winning settings of the three families are written to \texttt{configs/landmark.yaml} in one commit that names the winning trials, before the final training run. The family with the highest validation macro-F1 is then treated as the landmark model. If two trials of a family have exactly the same validation macro-F1, the one recorded first in the trials file is kept; there is no further tie-break.
