\section{Landmark Models}
\label{sec:landmark-models}

\subsection{Framework and Pipeline}

The landmark branch classifies a hand image in two stages. First, the MediaPipe hand landmarker finds one hand and returns 21 landmarks, each with $x$, $y$ and $z$ coordinates (Section~\ref{sec:feature-results}). The coordinates are normalised relative to the wrist and flattened into a vector of $21\times3=63$ values. Second, a classifier maps this vector to a probability for each of the 26 letters, in the class order of \texttt{data/processed/label\_map.json}. Three classifier families are trained on the same vectors: a support vector machine and a random forest from scikit-learn, and a multilayer perceptron (MLP) written in PyTorch. The code is in \texttt{src/signbridge/models/landmark\_models.py} and the training command is \texttt{src/signbridge/train\_landmark.py}.

\subsection{Classical Baselines}

\textbf{Support vector machine.} The SVM is a pipeline of a \texttt{StandardScaler} and an RBF-kernel \texttt{SVC}, with the regularisation $C$ and the kernel width $\gamma$ as hyperparameters. The AUC-ROC metric needs class probabilities, which an \texttt{SVC} does not give by default. The earlier plan was to switch on the \texttt{probability=True} option. In scikit-learn 1.9 that option is deprecated and planned for removal in version 1.11, so the \texttt{SVC} is wrapped in \texttt{CalibratedClassifierCV} with sigmoid calibration, 5 folds and \texttt{ensemble=False}. The calibrator is fitted on cross-validated decision values and the \texttt{SVC} is then refitted once on all training data. The output is an $n\times26$ matrix whose rows sum to 1, which is checked by a unit test. The calibration needs at least 5 training images per class and makes each SVM fit about six times more expensive than a plain \texttt{SVC}.

\textbf{Random forest.} The forest is a scikit-learn \texttt{RandomForestClassifier} with the number of trees and the maximum depth as hyperparameters. Tree models do not depend on feature scale, so no scaler is used.

\subsection{Multilayer Perceptron}

The MLP takes the 63 landmark values after standardisation. The mean and standard deviation are computed on the training split only. Each hidden block is a linear layer, a ReLU activation and dropout, and the output layer is a linear layer with 26 logits (Table~\ref{tab:landmark-mlp-layers}). The number of hidden layers is fixed by the configuration, while the hidden width and the dropout probability are tuned (Section~\ref{sec:landmark-hyperparameters}).

\textbf{Loss.} The loss is \texttt{CrossEntropyLoss}. It combines a log-softmax with the negative log-likelihood, so the network outputs raw logits and the softmax is applied only when probabilities are needed. Cross-entropy is the standard choice for a single-label problem with 26 mutually exclusive classes.

\textbf{Optimiser.} Training uses AdamW, which applies weight decay separately from the gradient step. Learning rate, weight decay and batch size are tuned. Batches are shuffled with a seeded generator, so a run with the same seed gives the same loss curve.

\textbf{Early stopping.} Training runs for at most 100 epochs. After each epoch the model is scored on the validation split, with dropout switched off. If the validation macro-F1 does not improve for 10 epochs, training stops and the weights of the best epoch are restored. Loss and accuracy of both splits are written for every epoch to \texttt{reports/tuning/mlp\_history.csv}, which gives the learning curves.

\subsection{Training Procedure and Use of the Splits}

One command trains the models and writes the predictions: \texttt{python -m signbridge.train\_landmark}. The seed comes from \texttt{configs/data.yaml} and is logged. The shared group-aware split (Section~\ref{sec:validation}) has 280 training, 60 validation and 60 test images per letter, before images without a detected hand are removed. The validation split is used for early stopping and for all hyperparameter selection. The test split is read only by the final run (\texttt{--final --evaluate-test}), which happens once, after the chosen settings have been committed to \texttt{configs/landmark.yaml}. The family with the highest validation macro-F1 is treated as the landmark model, and its prediction files are copied to \texttt{reports/predictions/landmark\_val.npz} and \texttt{landmark\_test.npz}. The files of the other families are kept next to them. No cross-validation was run.

\subsection{Limitation: Images Without a Detected Hand}

A landmark model can only predict for images in which MediaPipe finds a hand. Images without a detection are not counted as errors; they are missing from the prediction files, so landmark scores describe the detected images only and cannot be read as accuracy on all images. This is why the comparison with the CNN uses the common set of detected test images. In the 20-image check of Section~\ref{sec:feature-results}, a hand was found in 15 of 20 images. We kept the default confidence of 0.5, because a wrong landmark vector is worse than a missing one.
