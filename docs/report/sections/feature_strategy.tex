\section{Feature Strategy}
\label{sec:feature-strategy}

The project prepares two feature sets from each image, plus a numeric encoding of the labels. The code is in \texttt{data\_scripts/features/}.

\subsection{Hand Landmark Extraction}

\texttt{extract.py} turns images into landmark feature vectors. It uses the MediaPipe hand landmarker in single-image mode, limited to one hand per image. The model file is set by \texttt{paths.hand\_model} in \texttt{configs/data.yaml}; it is downloaded separately and kept out of Git.

\begin{enumerate}
  \item \textbf{Finding images:} images (\texttt{.jpg}, \texttt{.jpeg}, \texttt{.png}) are labelled by the name of their folder, converted to upper case. Folders whose name is not in the label map are skipped and counted. By default the script takes a random sample of 50 images per class, using \texttt{seed} from the configuration so the sample is the same on every run; the sample size can be changed on the command line, with 0 meaning all images.
  \item \textbf{Detecting the hand:} for each image the landmarker returns the 21 landmarks of the detected hand, or nothing if no hand is found. Unreadable images are logged and skipped.
  \item \textbf{Normalising:} the landmarks of each detected hand are normalised as described below, giving 63 values.
  \item \textbf{Caching:} the vectors, their class indices and the image paths are saved together in \texttt{landmark\_features.npz}, and one row per image (path, label, whether a hand was detected) is saved in \texttt{landmark\_detections.csv}. Both files go to \texttt{paths.processed\_dir} and are not committed.
\end{enumerate}

\subsection{Hand Landmark Normalisation}

Each landmark has $x$, $y$ and $z$ coordinates. The function in \texttt{landmarks.py} normalises one hand in two steps:
\begin{enumerate}
  \item \textbf{Translation:} the wrist (landmark 0) is subtracted from every landmark, so the wrist becomes the origin and the hand's position in the image no longer matters.
  \item \textbf{Scaling:} every coordinate is divided by the hand size, defined as the distance from the wrist to the base of the middle finger (landmark 9), computed over $x$, $y$ and $z$. The hand's size in the image, and so its distance from the camera, no longer matters.
\end{enumerate}
The result is flattened into a vector of 63 values (21 landmarks $\times$ 3 coordinates). The function rejects inputs of the wrong shape and hands whose size is zero. Tests check that shifting or scaling a hand leaves its features unchanged.

\subsection{Image Features}

For the image-based model, \texttt{images.py} converts each image to RGB, resizes it to $s \times s$ pixels, where $s$ is \texttt{image.size} in \texttt{configs/data.yaml} (currently 224), and scales pixel values from 0--255 to 0--1 as 32-bit floats.

\subsection{Label Encoding}

\texttt{labels.py} maps each class name to an integer index: A to Z become 0 to 25. With the \texttt{-{}-include-special} option, the three extra ASL classes follow as 26 to 28, so letter indices stay the same either way. The mapping is saved as \texttt{data/processed/label\_map.json}, which is committed so every script and model uses the same indices. The committed file contains the 26 letters only.
